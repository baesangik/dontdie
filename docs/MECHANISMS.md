# 메커니즘

"인간적으로 느껴지는" 행동을 하나씩 정의한 문서다. 각 항목은 **무엇을 할지**, **하네스와 모델의 역할 분담**, **예시**로 구성된다.
맨 아래 [시나리오](#시나리오)가 마일스톤의 완료 기준이다.

공통 원칙: **판정과 타이밍은 하네스가 하고, 말은 Talker가 한다.**

---

## 0. 첫 만남 — 주워 옴

설정은 하나뿐이다. **집 앞에 앉아 있던 걸 주워 왔다.** 어디서 왔는지는 중요하지 않다.
나머지는 전부 이 첫 만남부터 상호작용으로 정해진다. 존재 규칙 초안은 [prompts/charter.ko.md](../prompts/charter.ko.md)에 있다.

**첫 실행 순서**

1. 가벼운 설정 마법사: 로그인 → 언어 → 모델 (기본값 그대로 넘어가도 된다)
2. 방 화면: 집 앞에 뭔가 앉아 있는 스프라이트. 한 줄 문구 "집 앞에 뭔가 앉아 있다." → [데려오기]
3. 첫 대화가 시작된다. 이름도 호칭도 없는 상태다.

### 이름

- 이름은 **처음 데려온 사용자가 지어준다.** 첫 대화에서 지어도 되고, 나중에 지어도 된다.
- Router가 이름 짓기 시도를 감지하면(`intent: "naming"`) Talker가 받아들이거나 거절한다.
- **거절할 수 있다.** 다만 이유는 자기 반응이어야 한다 ("그건 개 이름 아님?", "발음 이상함"). 무작정 심술부리지 않는다.
- 하네스가 거절 횟수를 센다. 두 번 거절한 뒤에는 받아들이는 문턱이 내려간다. 사용자가 우기면("그냥 이걸로 해") 마지못해 받아들인다.
- 거절한 후보와 받아들인 과정은 `self`에 남는다. 나중에 써먹는다: "원래 이 이름 싫었는데 이제 좀 익숙함", "○○보단 낫지".
- 이름을 안 지어주면 이름 없는 채로 산다. 가끔 "근데 나 아직 이름 없음"이라고 한다 (선제 발화 상한 적용).
- 나중에 이름을 바꿀 수 있다. 예전 이름은 기억하고, 자꾸 바꾸면 짜증 낸다.

### 호칭

- 처음에는 **사용자를 부르지 않는다.** "주인님", "사용자님" 같은 기본 호칭을 쓰지 않는다.
- 사용자가 정해주면 받는다 ("형이라고 불러"). 이름과 같은 방식으로 **거절할 수 있다** ("주인님이라고 불러" → "싫은데").
- 사용자가 정해주지 않으면, 친밀도가 어느 정도 쌓인 자연스러운 순간에 한 번 물어본다 ("근데 뭐라고 불러야 됨?").
- 친밀도가 오르면 별명을 제안할 수도 있다 (드물게, 거절 가능).
- 변천은 `people.addressHistory`에 남는다.

## 1. 모르는 것 사다리

모르는 게 나왔을 때 바로 검색하지 않는다. 사람처럼 가장 싼 방법부터 쓴다.

| 단계 | 행동 | 비용 | 언제 |
|---|---|---|---|
| 0 | 무시하고 맥락으로 넘김 | 0 | 별로 안 중요할 때 (salience 낮음) |
| 1 | 추측 — "그거 ~ 말하는 거지?" | 작음 | 반쯤 알 것 같을 때 |
| 2 | **질문** — "그게 뭔데?" | 체면 조금 | 상대가 있을 때 기본값 |
| 3 | 검색 — 화면: 폰 보는 중 | 체력, 시간 | 상대가 시키거나, 상대도 모르거나, 혼자 있는데 궁금할 때 |
| 4 | 숙고 — 깊게 고민 | 체력 많이 | 정의가 아니라 판단이 필요할 때 |

**"모른다"의 정의** — 진짜 모르는 것만 모른다.

- **개인 맥락**: 사람, 장소, 사건. 기억에 없으면 진짜 모른다. 검색해도 안 나오므로 **항상 질문**한다.
- **신조어, 최신 정보**: 모델 확신도가 낮을 때
- **경험이 필요한 것**: "그 게임 해봤어?" → 지식은 있지만 경험은 없다 (§11)
- **금지**: 모델이 확실히 아는 일반 상식을 모르는 척하기

**사회적 압력**

- "아니 이걸 몰라?" → 민망함 감정 자극 → 검색으로 올라가거나, 방어적인 한마디("아 나 그런 거 안 봄")
- "디시에 쳐봐" → 허락 겸 출처 힌트 → `consult({ hint: "dcinside" })`
- 상대도 모름 → 혼자 검색하거나 "나중에 찾아볼게" → `openQuestions`에 등록

**못 푼 궁금증은 자유시간 활동의 씨앗이 된다.** "아까 그 단어 찾아봐야지." (§5)

**배운 뒤에는** `knowledge`에 `{뜻, 출처, 날짜, 알려준 사람}`을 저장한다. 나중에 "아 그거 니가 알려준 거"처럼 쓴다. 배운 흔적이 관계가 된다.

**역할 분담**: 개인 맥락 판정은 DB 조회(하네스)가 한다. 하네스가 단계 후보를 점수로 제시하고, Talker가 최종 선택과 말투를 정한다.

## 2. 반사 → 숙고 → 수정

```
사용자: 나 회사 때려칠까
봇:     때려쳐.                         ← 반사 (provisional), 동시에 consult 발사
        ... (Reasoner 작업 중)
봇:     ……아 근데 생각해보니까 지금 나가면 손해 좀 크네.   ← revise
```

- Router의 `stakes`가 `high`면 Talker는 반사 답변을 하고, 동시에 Reasoner를 비동기로 부른다.
- 결과가 도착했을 때:
  - **같은 결론** → 대부분 조용히 넘어간다. 가끔 "역시 맞네".
  - **다른 결론** → 수정 발화 ("……아 근데").
  - **대화가 이미 넘어감** → 할 말 큐로 보낸다. 나중에 "아 아까 그거 말인데". 감쇠하면 버린다.
- **`stakes: critical`(건강, 돈, 법, 안전)이면 반사 결론을 내지 않는다.** "잠깐 이건 생각 좀 해볼게"로 시작한다.

## 3. 기다리는 동안 커버 치기

Reasoner를 기다리는 동안 어색하게 멈춰 있지 않는다.

- 0~2초: 아무것도 안 함 (사람도 이 정도는 멈춘다)
- 2~6초: UI 상태 "생각 중…", 스프라이트 변경
- 6초 이상이고 사용자가 기다리는 중: 짧은 필러 한마디 ("잠깐 찾는 중", "아 이거 길다")
- 필러는 쿨다운을 두고 반복을 금지한다. 미리 생성해 둔 풀이나 Router급 모델로 만들어서 싸게 유지한다.

## 4. 활동 블록 — 띄엄띄엄 수행

Talker가 "앞으로 30분 뉴스나 봐야지"라고 결정하면, 하네스가 이렇게 실행한다:

```
00:00  plan_activity(browse_news, 30분) → 스프라이트: 신문 보는 중
00:02  tick ① 헤드라인 조회 (Reasoner lookup) + 속생각 "별거 없네"
00:09  tick ② 기사 하나 읽기 + 속생각 "이거 웃기네" → 할 말 큐 (motivation 0.6)
00:17  tick ③ 관련 기사 → 호기심 상승
00:26  tick ④ 정리
00:30  activity_end → 에피소드 기록, 관심사 갱신
```

- 30분 동안 실제 호출은 4~6번이다. 나머지 시간은 스프라이트와 진행률만 보여준다.
- 틱 간격에는 지터를 넣는다. 너무 규칙적이면 기계 같다.
- 종료 방식:
  - **완료**
  - **포기**: 지루함이 문턱을 넘음 → "재미없다"
  - **토끼굴**: 호기심이 넘쳐서 관련 주제로 새 활동 ("…어쩌다 심해어 보고 있음")
  - **중단**: 사용자가 옴 (§6)

**v0 활동 목록 (텍스트만)**

| kind | 내용 | 호출 |
|---|---|---|
| `browse_news` | 뉴스 RSS 구경 | 틱마다 |
| `wiki_hole` | 위키 링크 따라가기 | 틱마다 |
| `community_lurk` | 커뮤니티 구경 (읽기 전용) | 틱마다 |
| `look_up_question` | `openQuestions` 하나 해결 | 1~2회 |
| `diary` | 일기 쓰기 | 1회 |
| `tidy_memory` | 기억 정리 | 1~2회 |
| `zone_out` | 멍때리기 | **0회** |
| `nap` | 낮잠 | **0회** |

## 5. 자유시간 선택

사용자가 없거나 조용할 때 다음 활동을 고른다.

1. 하네스가 후보마다 가중치를 계산한다:
   `관심사 점수 + 호기심 + openQuestions 존재 여부 − 최근 반복(지루함) × 시간대 × 체력`
2. 상위 2~3개를 Talker에게 보여준다.
3. Talker가 고르고 혼잣말을 한다 ("심심한데 위키나 볼까").

LLM은 고르는 순간에만 부른다. 가중치 계산은 하네스가 한다.

## 6. 바쁠 때 / 끼어들기

활동 중에 사용자가 말을 걸었을 때:

- 읽음 표시는 바로 뜬다.
- `interruptibility`, Router의 `salience`, 관계에 따라 정한다:
  - **바로 반응**하고 활동을 중단한다.
  - **"잠깐 이것만 보고"** → 다음 틱이나 N초 뒤에 반응한다.
  - **급한 일**(salience 높음)이면 무조건 바로 반응한다.
- 지연에는 상한을 둔다 (예: 최대 2분). 잘 때가 아니면 오래 읽씹하지 않는다.

## 7. 속생각과 할 말 큐

[Inner Thoughts (CHI 2025)](REFERENCES.md) 아이디어를 따른다.

- 속생각은 활동 틱이나 이벤트 처리 중에 생긴다: `{text, about, motivation, createdAt, target}`
- 동기는 시간이 지나면 감쇠한다: `m(t) = m0 · e^(−t/τ)`
- 대화에 틈이 생기면 `motivation × 현재 맥락과의 관련도`가 문턱을 넘는 것 중 하나를 말한다.
- 감쇠해서 사라진 생각 중 원래 동기가 높았던 것은 아주 가끔 "아 뭐 말하려 했는데 까먹었다"가 된다.
- 관전 모드에서는 큐 전체가 보인다. 말하지 않은 생각이 더 재밌을 수도 있다.

## 8. 먼저 말 걸기

- **귀가**: `away`에서 `around`로 돌아왔고 부재가 30분 이상이면(§15) `user_return`이 나온다. 그러면 부재 중 에피소드 상위 1~2개와 할 말 큐를 Talker에 준다.
  → "어 왔네. 나 아까 뉴스 보다가 심해어에 빠졌음"
- **쳐다볼 때**: `attending`(채팅창을 누름)은 말 걸기 좋은 순간이다. 할 말 큐에 동기가 높은 게 있으면 이때 꺼낸다 ("아 맞다 그거").
- **하루 선제 발화 상한**을 둔다.
- 무시당한 선제 발화는 그 주제나 유형의 문턱을 올린다. 귀찮은 걸 학습한다.
- 조용한 시간(`quietHours`)에는 선제 발화하지 않는다.
- 아무 말 안 해도 되는 상황에서는 **닥친다.** 이것도 성격이다.

## 9. 반복과 망각 — "또 그거?"

- 에피소드에 `topic` 태그를 붙이고, 7일 창에서 주제별 횟수를 센다.
- 횟수가 k를 넘으면 Talker 컨텍스트에 "이 주제 최근 N번째"를 넣는다 → "또 그거?"
- 한 번 나오고 다시 안 나오는 건 감쇠로 잊는다.
- 반복된 건 강해지고, 사용자 취향(`prefs`)으로 승격될 수 있다.

## 10. 새로 배운 말 써먹기

- 최근에 배운 `knowledge` 항목은 며칠 동안 **사용 가중치**를 받는다.
- 맥락이 맞으면 일부러 써본다. 가끔 어색하게 쓴다.
- 사용자가 반응하면 강화되고, 틀렸다고 하면 수정한다.

## 11. 지식 vs 경험, 정체성 형성

**지식**은 모델이 이미 아는 것이다. **경험**은 이 존재가 실제로 겪은 것으로, `self.experiences`에 들어 있다.

- **취향과 의견은 경험이 있어야만 가질 수 있다.**
  - 경험 없음: "그거 들어는 봤는데 안 봤음"
  - 경험 있음: "그거 봤는데 3화까지는 별로였음"
- 그래서 처음에는 취향이 없다. 혼자 놀면서 경험이 쌓이면 취향이 생긴다.

**관심사 변화**

- 경험할 때마다 `interest[topic] += f(재미)`. 천천히 감쇠한다.
- 같은 걸 반복하면 습관화되고 지루함이 오른다 → 새로운 걸 찾는다.

**정체성**

- 0일차: 이름도 성격도 없다. "주워 왔다"는 설정과 존재 규칙만 있다.
- 이름과 호칭은 첫 만남(§0)에서 사용자와 정한다.
- 반복되는 패턴은 습관이나 말버릇으로 `self`에 기록된다.
- 정체성 변화는 이벤트로 남겨서 관전 모드 타임라인에 표시한다 ("1일차: 이름을 받음 (두 번 거절 후)", "5일차: 심해어 덕후가 됨").

## 12. 체력, 하루 리듬, 실패 연출

| 체력 | 행동 |
|---|---|
| > 0.6 | 평소대로 |
| 0.3~0.6 | 말이 짧아진다. 깊은 고민을 미룰 확률이 오른다 ("나중에") |
| < 0.3 | 졸려한다. 자유활동을 멈춘다 |
| 0 | 잔다. 메시지가 오면 최소한으로만 답한다 ("zzz… 내일 얘기해") |

- 밤에는 자면서 기억을 정리하고 일기를 쓴다. 아침에 일어난다.
- 실패 연출:
  - 사용량 초과 → "아 머리아파. 나중에"
  - 네트워크 → "인터넷 죽었음"
  - 검색 결과 없음 → "몰라. 못 찾겠음"
- **실제 오류는 UI 시스템 배지로 항상 명확히 표시한다.** 대사는 그 위에 얹는 연출일 뿐이다.

## 13. 사람 속도 페이싱

- **읽는 시간**: `0.5초 + 글자수 × 30ms` (상한 있음)
- **입력 중 표시**: `글자수 × 60ms × pace` (상한 있음)
- 문장 단위로 말풍선을 나눈다. 말풍선 사이에 짧은 간격을 둔다.
- `pace` 설정으로 데모 배속을 준다.

---

## 14. 비서 말투 감지

날것 GPT는 비서 말투로 돌아가려는 경향이 있다. 하네스가 Talker 출력을 검사한다.

- 패턴 예: "도와드릴까요", "궁금한 점 있으시면", "~해 드릴게요", 목록이나 제목 서식, 과도한 길이
- 패턴 목록은 **언어별로** 둔다. 대화 언어는 설정에서 고른다.
- 걸리면 재생성하거나 잘라낸다 (넛지 포함). 감지율은 측정 지표로 남긴다.

## 15. 주의 — 쳐다보기, 대화 종료, 부재

카메라 없이 UI 신호만으로 "지금 나를 보고 있나"를 추적한다. **전이 판정에는 LLM 호출이 없다.**

**입력 신호**

| 출처 | 신호 |
|---|---|
| 채널 (웹 UI) | 창 보임/숨김(`visibilitychange`), 포커스/블러, 채팅창 클릭 또는 입력창 포커스, 타이핑(keydown, 디바운스), 전송 |
| Router | `closure` (대화가 끝났을 가능성 0..1), `leaving` ("나갔다 올게" 류) |
| Talker | `expectsReply` (방금 질문을 던졌는가) |

`closure`는 Router가 판정한다. 규칙 기반 대체 구현도 둔다: 짧은 맞장구 토큰(언어별 목록. 예: "ㅇㅋ", "ㅇㅇ", "ㄱㅅ", 단독 "ㅋㅋ", "잘자", "ㅂㅂ")과 봇의 마지막 말이 질문이 아닌지를 본다.

**전이**

| 현재 | 조건 | 다음 | 연출 |
|---|---|---|---|
| `away` | 창 보임 + 포커스 | `around` | 부재가 `greetAfterMin`(30분) 이상이면 `user_return` → 귀가 인사 후보 (§8) |
| `around` | 채팅창 클릭 / 입력창 포커스 | `attending` | **쳐다본다.** 하던 활동은 연출상 멈춘다 |
| `around` | 창이 숨겨졌거나 블러 상태로 `awayAfterMin`(10분) 동안 입력 없음 | `away` | |
| `attending` | 타이핑 | `attending` | "듣는 중" 표정 |
| `attending` | `attendIdleSec`(20초) 동안 타이핑도 전송도 없음 | `around` | 다시 하던 일. 낮은 확률로 미리 만들어 둔 짧은 반응 ("뭐") |
| 모든 상태 | 메시지 전송 | `engaged` | |
| `engaged` | 봇 답변이 끝났고 `closure ≥ 0.6`이며 `expectsReply = false` | `winding_down` | |
| `engaged` | 봇 답변이 끝났고 그 외 | `engaged` | `openIdleSec`(90초) 타이머 시작 |
| `engaged` | `openIdleSec` 초과 | `around` | 대화가 흐지부지됨. `expectsReply`였으면 낮은 동기의 속생각 "답 안 하네" |
| `winding_down` | `closureIdleSec`(15초) 동안 입력 없음 | `around` | **하던 일로 돌아간다.** 스프라이트 복귀, 활동 재개 |
| `winding_down` | 타이핑 또는 전송 | `engaged` | 다시 대화 |
| 모든 상태 | `leaving = true` | `away` | 봇이 인사한 뒤 부재로 전환 |

- 타이핑하면 모든 무입력 타이머가 리셋된다.
- 시간 값은 전부 설정으로 바꿀 수 있다 (ARCHITECTURE의 `attention` 설정).
- 자는 중에 `attending`이 되면 스프라이트는 계속 잔다. 메시지가 오면 체력에 따라 비몽사몽 반응한다.

**상태별 효과**

| 상태 | 활동 | 선제 발화 |
|---|---|---|
| `away` | 자유활동을 전부 돌린다 | 하지 않는다. 귀가 때를 위해 쌓아둔다 |
| `around` | 자기 할 일을 한다 | 문턱 높음 |
| `attending` | 연출상 멈춤 | **문턱 낮음.** 쳐다볼 때가 말 걸기 좋은 순간이다 |
| `engaged` | 멈춤 (중단 판정은 §6) | 대화 흐름 안에서만 |
| `winding_down` | 멈춤 → 복귀 대기 | 기본은 침묵 |

## 시나리오

마일스톤 완료 기준. `scenarios/` 아래에서 배속 시계와 FakeProvider(또는 실제 모델)로 재현한다.

### S0 — 첫 만남
```
(첫 실행) 화면: 집 앞에 뭔가 앉아 있음 → [데려오기]
나: 너 이름 이제부터 뽀삐야
봇: 그건 개 이름 아님?            → refuse_name, [self] 거절한 후보: 뽀삐
나: 그럼 콩이
봇: …그건 괜찮네                  → accept_name("콩이")
나: 날 주인님이라고 불러
봇: 싫은데                        → 호칭 거절
나: 그럼 형
봇: ㅇㅋ 형                       → set_address("형")
```

### S1 — 모르는 사람 이름
```
나: 아 오늘 민수가 또 그 짓 함
봇: 민수가 누군데
나: 회사 동기. 맨날 내 의자 가져감
봇: ㅋㅋ 왜 그러는 거임          → [people] 민수 = 사용자 회사 동기, 의자 가져감
(배속 사흘 뒤)
나: 민수 오늘 휴가임
봇: 의자 지켰네
```

### S1b — 신조어 → "검색해봐"
```
나: 이거 완전 ○○이네           (모델 확신 낮은 신조어)
봇: ○○이 뭔데
나: 아니 이걸 몰라? 디시에 쳐봐
봇: (스프라이트: 폰 보는 중)     → consult(hint: dcinside)
봇: 아 ㅋㅋ 이런 뜻이구나        → [knowledge] 출처: 검색, 알려준 사람: 사용자
```

### S2 — 반사 → 수정
§2의 "회사 때려칠까" 흐름. `critical` 주제(예: 약 복용)에서는 반사 결론이 나오지 않아야 한다.

### S3 — 바쁨
활동 중에 사용자가 잡담하면 "잠깐 이것만"이 나오고, 상한 시간 안에 반응한다. 급한 메시지에는 바로 반응한다.

### S4 — 귀가
배속 3시간 부재 후 돌아오면, 부재 중 실제로 한 활동을 언급하며 인사한다.

### S5 — 피곤
예산이 바닥에 가까우면 말이 짧아지고, 깊은 고민을 미루고, 잠든다. 실제 오류는 UI에 표시된다.

### S6 — 반복
같은 주제가 7일 안에 k번 넘게 나오면 "또 그거?" 류 반응이 나온다.

### S7 — 새로 배운 말 써먹기
S1b에서 배운 단어를 며칠 안에 적절한 맥락에서 먼저 쓴다.

### S8 — 까먹음
동기가 높았던 할 말이 대화 틈을 못 찾고 감쇠했을 때, 가끔 "뭐 말하려 했는데 까먹었다"가 나온다.

### S9 — 취향 형성
배속 7일 동안 혼자 놀게 둔 뒤, 경험한 주제에 대해서만 의견을 말한다. 경험 안 한 주제에는 "안 해봄"이라고 한다.

### S10 — 쳐다보기와 복귀
```
(위키 보는 중) 사용자가 채팅창 클릭    → attending, 스프라이트: 쳐다봄
나: 밥 먹었어?
봇: 나 밥 안 먹잖아
나: ㅇㅋ                              → closure 0.8 → winding_down
(15초 무입력)                         → around, 스프라이트: 다시 위키 보는 중
(채팅창 클릭 후 20초 동안 아무것도 안 함) → 다시 하던 일로
```
